# CakeBazar Product Design Principles

# اصول طراحی محصول CakeBazar

## Purpose

This document defines the principles that guide product, design, engineering,
operations, AI, and business decisions inside CakeBazar.

If a decision conflicts with these principles, the principles win.

این سند اصولی را تعریف می‌کند که تصمیم‌های محصول، طراحی، توسعه، عملیات و هوش
مصنوعی CakeBazar باید از آن پیروی کنند.

## Core Belief

People do not only buy cakes. They buy confidence that an important moment will
go well.

مردم فقط کیک نمی‌خرند. آن‌ها آرامش خاطر برای یک لحظه مهم را می‌خرند.

## Principle 1: Trust Before Growth

Growth without trust creates fragile demand. Trust creates repeat orders,
referrals, seller quality, and long-term defensibility.

Product questions:

- Does this increase customer confidence?
- Does this reduce celebration risk?
- Does this make seller quality easier to understand?
- Does this make the marketplace safer?

## Principle 2: Celebration Outcome Over Transaction

The product is not complete when an order is submitted. The product succeeds when
the celebration succeeds.

Measure:

- Successful order completion
- On-time delivery or pickup
- Customer satisfaction after the event
- Repeat purchase intent

## Principle 3: Evidence At Every Decision Point

Customers should never have to guess whether a seller is reliable.

Evidence can include:

- Verified seller badge
- Real product photos
- Recent reviews
- Response time
- Cancellation history
- Delivery and pickup options
- Clear pricing expectations

## Principle 4: Warm Luxury, Not Decoration

CakeBazar should feel warm, premium, and emotionally safe. Luxury should come
from clarity, craft, photography, spacing, language, and trust signals rather
than heavy visual effects.

Visual direction:

- Warm neutrals
- Rich accent colors
- Realistic cake photography
- Strong text contrast
- Cinematic celebration imagery when it serves the story

## Principle 5: Mobile First, Family Context First

Most discovery and ordering will happen on mobile, often while a customer is busy
planning a family event.

Design for:

- Fast scanning
- Large tap targets
- Short decision paths
- Persistent trust signals
- Easy sharing with family members

## Principle 6: Seller Clarity Before Marketplace Scale

A marketplace cannot scale if sellers are confused. Seller onboarding must be
clear, respectful, and operationally realistic.

Seller experience should answer:

- What do I need to provide?
- How do I get verified?
- How do I receive orders?
- How do I protect my time?
- How do I improve my reliability score?

## Principle 7: Simple Before Powerful

The first version should solve the most important flows simply. Advanced tools
should only be added after the core marketplace has evidence of demand.

Prefer:

- Clear categories over complex personalization
- Order requests before full checkout complexity
- Manual admin review before automation
- Focused city launch before broad geographic coverage

## Principle 8: AI Invisible Until Valuable

AI should reduce friction or increase trust. It should not become visible noise.

Good AI uses:

- Suggest cake styles from customer intent
- Improve listing quality
- Help sellers write descriptions
- Detect missing order details
- Support moderation and fraud review

Bad AI uses:

- Decorative chatbots with no operational value
- Overpromising custom design generation
- Replacing seller trust with vague automation

## Principle 9: Real Photos Beat Generic Beauty

Customers need to inspect the real thing. Repeated, unrealistic, or generic
images damage trust.

Photography rules:

- Prefer actual seller work
- Separate inspiration images from real portfolio images
- Label generated or reference visuals clearly
- Use category-specific imagery for birthdays, weddings, children, family events,
  and corporate occasions

## Principle 10: Marketplace Before Ecosystem

CakeBazar should grow in this order:

1. Marketplace
2. Trusted marketplace
3. Celebration platform
4. Supplier network
5. Academy
6. AI platform
7. Celebration operating system

Do not build the ecosystem before the marketplace works.

## Principle 11: Build Systems, Not Random Features

Features create screens. Systems create a company.

Core systems:

- Seller verification
- Reliability scoring
- Review quality
- Order request workflow
- Category taxonomy
- Admin moderation
- Customer feedback loop

## Principle 12: Measure Outcomes, Not Activity

Bad metrics:

- Page views
- Number of screens
- Number of listed features

Good metrics:

- Celebration success rate
- Order request conversion
- Verified seller supply
- Seller response time
- Repeat purchase rate
- Review quality

## Design North Star

CakeBazar should feel like the safest and most trusted way to celebrate.

## Decision Checklist

Before shipping a product decision, ask:

- Does it increase trust?
- Does it reduce customer anxiety?
- Does it help good sellers win?
- Does it make the order outcome more reliable?
- Is it simple enough for the MVP?
- Can we measure whether it worked?
