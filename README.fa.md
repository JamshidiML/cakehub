# CakeBazar | کیک‌بازار

> آزمایش یک مارکت‌پلیس اعتمادمحور برای کیک‌های سفارشی و شیرینی‌های خانگی.

**مرحله فعلی:** بازتنظیم بنیان‌گذار و اعتبارسنجی مسئله — نه یک مارکت‌پلیس آماده بهره‌برداری.

**نسخه انگلیسی:** [README.md](README.md)

## تز محصول

مردم فقط کیک نمی‌خرند؛ آن‌ها می‌خواهند یک لحظه مهم را از عدم قطعیت و شکست محافظت کنند.

بنابراین اولین وظیفه CakeBazar ساخت بزرگ‌ترین کاتالوگ نیست. وظیفه نخست این است که تعریف نیاز مشتری، پیدا کردن فروشنده مناسب و انجام مطمئن سفارش را ساده‌تر و قابل‌اعتمادتر کند.

## نقطه ورود استراتژیک

از یک شهر، یک بخش محدود از مناسبت‌ها و یک فرایند مدیریت‌شده سفارش شروع می‌کنیم:

1. مشتری یک درخواست ساختاریافته ثبت می‌کند.
2. CakeBazar کامل بودن درخواست را بررسی می‌کند.
3. درخواست برای گروه کوچکی از فروشندگان که به‌صورت دستی بررسی شده‌اند ارسال می‌شود.
4. موجود بودن ظرفیت و پیشنهادهای قیمت جمع‌آوری و مقایسه می‌شوند.
5. مشتری فروشنده را انتخاب می‌کند.
6. CakeBazar تا زمان برگزاری مناسبت، نتیجه سفارش را پیگیری و ثبت می‌کند.

این یک **پایلوت مارکت‌پلیس مدیریت‌شده یا Concierge Marketplace** است، نه یک مارکت‌پلیس باز و کامل.

## امروز چه چیزی وجود دارد؟

### پیاده‌سازی شده

- یک اپلیکیشن Next.js در مسیر `apps/web`
- یک نمونه اولیه سینمایی و فارسی از صفحه فرود
- مجموعه بزرگی از اسناد محصول، کسب‌وکار، مالی، عملیات، معماری و ایده‌ها
- یک ممیزی جامع مخزن در مسیر `docs/audit`

### هنوز پیاده‌سازی نشده

- احراز هویت
- دیتابیس و داده پایدار مارکت‌پلیس
- فرایند ورود و اعتبارسنجی فروشنده
- فرایند درخواست مشتری و دریافت پیشنهاد قیمت
- مدیریت سفارش
- پرداخت
- نظرها و سیگنال‌های اعتماد مبتنی بر تراکنش واقعی
- داشبورد عملیات و ادمین
- ابزارهای اندازه‌گیری و تحلیل رفتار
- استقرار پروداکشن و پشتیبانی عملیاتی

قابلیت‌های برنامه‌ریزی‌شده هرگز نباید به‌عنوان قابلیت‌های منتشرشده معرفی شوند.

## هدف فاز صفر

اعتبارسنجی این فرضیه که CakeBazar برای یک کاربرد محدود سفارش کیک سفارشی، می‌تواند به‌طور تکرارپذیر نتیجه‌ای بهتر از اینستاگرام، پیام مستقیم، جست‌وجو یا معرفی شخصی ایجاد کند.

فاز صفر فقط زمانی موفق است که درخواست‌های واقعی مشتری به پاسخ واقعی فروشنده، پیشنهاد قیمت، سفارش انجام‌شده و نتیجه قابل‌تأیید پس از جشن منجر شوند.

## مرزهای محصول

تا قبل از عبور از دروازه‌های شواهد فاز صفر، موارد زیر ساخته نمی‌شوند:

- امتیاز قابلیت اطمینان محاسباتی
- تضمین گسترده موفقیت جشن
- سیستم پیشنهاددهی هوش مصنوعی
- پلتفرم جشن‌های سازمانی
- آکادمی
- مارکت‌پلیس تأمین‌کنندگان
- خدمات مالی یا خرید اقساطی
- شبکه لجستیک سراسری
- پلتفرم کامل مدیریت رویداد

هوش مصنوعی می‌تواند به‌صورت داخلی برای افزایش سرعت تحقیق، کدنویسی، بهبود محتوا، کمک به تعدیل محتوا و عملیات استفاده شود؛ اما نباید جایگزین شواهد واقعی بازار شود.

## ترتیب بررسی بازارها

ایران و آلمان هر دو بازارهای اکتشافی هستند، اما CakeBazar دو مارکت‌پلیس را هم‌زمان راه‌اندازی نخواهد کرد.

در یک دوره اکتشاف زمان‌بندی‌شده، هر شهر کاندید بر اساس معیارهای زیر امتیاز می‌گیرد:

- دسترسی به تعداد کافی فروشنده
- شدت مسئله مشتری
- تمایل به انجام تراکنش از طریق پلتفرم
- امکان‌پذیری تولید، تحویل و انجام سفارش
- آمادگی قانونی و ایمنی غذایی
- امکان‌پذیری پرداخت
- دسترسی بنیان‌گذار و سرعت عملیات
- هزینه احتمالی جذب کاربر

بازار نخست بر اساس شواهد انتخاب می‌شود، نه ترجیح شخصی بنیان‌گذار.

## اجرای محلی

```bash
cd apps/web
npm ci
npm run dev
```

پیش از باز کردن Pull Request:

```bash
npm run lint
npm run build
```

به‌محض شروع جریان‌های واقعی محصول، تست نیز باید اضافه شود.

## مدل همکاری: بنیان‌گذار + ChatGPT + Codex

- **بنیان‌گذار:** چشم‌انداز، دسترسی به کاربران و تصمیم نهایی درباره ریسک و سرمایه
- **ChatGPT به‌عنوان هم‌بنیان‌گذار و استراتژیست:** ترکیب تحقیقات، استراتژی محصول، اولویت‌بندی، تدوین مشخصات، نقد عمیق و حفظ حافظه تصمیمات
- **Codex:** پیاده‌سازی محدوده‌دار، بازآرایی کد، تست، مستندات فنی و اصلاح Pull Requestها

تمام کارهای پیاده‌سازی باید به یک Issue یا مشخصات وظیفه قابل ردیابی باشند، روی شاخه جداگانه انجام شوند، از طریق Pull Request بررسی شوند و معیارهای پذیرش داشته باشند.

- `NAME.md`
- `NAME.fa.md`

کد و تنظیمات ماشینی مستقل از زبان هستند و دو بار کپی نمی‌شوند. تمام متن‌های قابل‌مشاهده برای کاربر باید آماده بومی‌سازی باشند.
